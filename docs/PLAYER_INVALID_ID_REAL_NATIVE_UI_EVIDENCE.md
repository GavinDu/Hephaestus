## Honest UI evidence contract

Production `PixiPlayerSheet` refuses noncanonical IDs before `PlayerWebViewPool.playerURL` can create a URL, sets a fixed `.invalidPackage` message, suppresses ShareLink and preserves native Return to feed. The first exact-head iPhone CI observed the return button's **actual accessible frame was only 20.33pt high** despite an outer `.frame(minHeight:)`; the real recovery label is now expanded **inside** the button, with a bordered hit area and 44pt minimum dimensions. Pure predicates alone did not verify its actual view layout or accessibility on iPhone/iPad. The app's `HephaestusApp.WindowGroup` now has a **compile-time `#if DEBUG && targetEnvironment(simulator)`** test-only entry with launch flag `--ui-test-invalid-player-id`. It presents the **real shipping `PixiPlayerSheet`** via SwiftUI `.sheet` using grammar-invalid constant `bad/id` over the genuine normal `ContentView`. It does not publish/seed a game, spoof a creator or backend response, bypass authorization, instantiate a second interpreter or grant any native JS control channel. This entry and the identifier literal are excluded from Release and physical-device builds. The normal real feed remains responsible for its own network/availability, so **we do not assert the entire app made no network requests**.

Two real `HephaestusUITests/PlayerSmokeTests` XCTest methods exercise standard and system Accessibility5 text size on actual iOS simulators: wait for native terminal fixed text, assert no `WKWebView`, no player Share or Retry, check the actual Return to feed native 44pt hitbox, tap it, wait for true sheet dismissal, and attach original before/after screenshots. They are included automatically in the existing strict `-only-testing:HephaestusUITests/PlayerSmokeTests` jobs on both iPhone and required iPad Player Presentation; no test skip or fictional successful positive game. A Python source regression guard checks route isolation and production failure state wiring, and runs in the existing `xcode` CI job.
