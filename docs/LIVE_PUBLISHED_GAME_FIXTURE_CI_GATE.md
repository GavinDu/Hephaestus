# Native real published feed/game fixture prerequisite

Parent [Runtime Epic #202](https://github.com/GavinDu/Hephaestus/issues/202), persistent live creator and game fixture [#288](https://github.com/GavinDu/Hephaestus/issues/288), independently scoped smoke prerequisite [#345](https://github.com/GavinDu/Hephaestus/issues/345).

## Why HTTP 200 is not gameplay readiness

The mandatory `ios.yml` and `player-presentation.yml` simulator workflows previously warmed `/v1/feed` until HTTP 200, then treated the endpoint as ready. However a transport-success response may contain zero games or ownerless content. Live iPhone/iPad tests `testDiscoverLaunchesPlayer`, `testArcadePulseSocialWriteFailureDoesNotHideLiveGame`, and creator profile assertions require a **real playable owner-linked feed post**, not merely a web server answering. A fallback Library or a fabricated game cannot turn those tests green.

The dependency-free `tools/test-feedback/verify-live-game-fixture.py` checks the **public deployed** feed over HTTPS using bounded response size (2 MB), timeouts, attempts and redirect-denial. It requires a real nonblank allowlisted `game_id` and nonblank `owner_id` plus `status:ready`, `visibility:public`, non-quarantined, and moderation **not pending/rejected**. The existing backend `canDeliver` still supports older shipped inventory with an unset moderation field; requiring an explicit `approved` field or nonzero `published_version` from old responses would create a false backend outage. Full independently approved test-publisher provisioning remains #288. For up to five real eligible entries, it independently fetches the matching same-origin `/v1/games/{game_id}/package` and requires the same `gameId`, canonical `packageFormatVersion`/`minRuntimeVersion`/`irVersion` and matching nonempty `ir.irVersion`. The response must have `application/json` content type; HTTP 200 HTML, invalid JSON or cross-origin redirects are not success. No credentials, private player data, full game IDs, or full feed JSON are logged: a SHA-256 ID prefix is recorded only after the real package passes.

A missing/empty feed, missing owner, rejected/moderated/nonpublic game, bad JSON, cross-origin redirect, package failure or mismatched package now fails CI **before any long simulator smoke run** with `LIVE_FIXTURE_NOT_READY` and a specific `::error` annotation. This is a *new hard gate*, not a warning. Original Xcode/player-smoke/iPad evaluator and real screenshot assertions remain required. On healthy public fixtures the existing tests still run, and this preflight does not claim that the remote service remains healthy throughout the run.

### Independent tests and review

- Offline Python unittest covers eligible game/package success, invalid privacy/status/quarantine/owner/ID, missing/empty feed, package schema and IR-version mismatch, HTTP 200 HTML/bad JSON, and legacy unset moderation. A **separate fast Ubuntu GitHub Actions job** runs the precise fixture tests while the existing Xcode job also retains its comprehensive `tools/test-feedback` checks. No required macOS test is bypassed.
- Both native iPhone and iPad CI workflow paths run the same preflight script. Do not silently bypass the gate on a failing request. No Replit workflow/model or synthetic game seeding is used.
- Senior game-engine architect challenge: Does preflight match deployed `canDeliver` and the actual runtime's package? Are HTTP redirects, malformed/huge inputs and role leakage bounded? Does the real publisher have a retrievable profile and a live game throughout the test? The latter remains a **separate P0 fixture provisioning task** #288.
- Merge #345 only after **all seven exact-head native Xcode/unit, player smoke, iPad evaluator and backend/presentation jobs pass**. The new preflight must not be treated as proof of deterministic game execution, first GPU compositor frame, WebKit memory/thermal, trust score or physical iPhone/iPad hardware. These remain open in Epic #202.

Rollback reverts only the preflight module/tests, workflow prerequisite and this documentation.

### 2026-11-14 live-package failure classification

A real required [iPad evaluator run #43652844928](https://github.com/GavinDu/Hephaestus/actions/runs/43652844928) found `feed_count=3, eligible_count=3` but none of the three public games passed the same-origin package contract. The previous preflight swallowed all per-package reasons, so the result could not distinguish a missing public package from invalid HTML/JSON or a versioned envelope mismatch. The subsequent narrow source improvement records only **bounded category counts** (`http_404`, `http_403`, `transport`, `redirect`, `not_json`, `invalid_json`, `too_large`, `invalid_envelope`, `unavailable`). It never emits raw upstream error text, creator/game identities, package URLs or response bodies, and still fails the job if no real package qualifies. Extra offline negative tests verify categories and privacy.

This categorization is observability **only**: it does not create or repair a game package, mark a game moderated, or remove the required player smoke; keep fixture owner #288 and runtime Epic #202 OPEN until real published content and native CI are verified. Source-only review is not proof of live deployment health.

### Decomposed envelope mismatch from required CI

[Exact-head iPad evaluator #43658762628](https://github.com/GavinDu/Hephaestus/actions/runs/43658762628) confirmed the live public feed has three eligible owner-linked entries, each with HTTP 200 JSON package delivery but a failed envelope shape: `package_failure_breakdown=invalid_envelope:3` on all three bounded attempts. This disproves the narrower hypothesis that the immediate failure is only 403/404/transport. It **does not prove** which mandatory field differs, nor that the live backend is at the same schema version as the current `internal/api/package.go` source.

The next independently testable preflight diagnostic subdivides `invalid_envelope` into only fixed field categories: nonobject, game ID mismatch, missing package format/minimum runtime/version, missing/invalid IR or nested IR-version mismatch. No source value, personal creator/game identity, raw response, URL or token is exposed; the hard CI gate remains failing until a **real published package** matches the deployed player contract. Never change package acceptance solely to make a fixture test green without auditing native/backend compatibility and privacy.
